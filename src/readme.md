**ПОРОЖДАЮЩИЕ ПАТЕРНЫ**

1/) Factory
- объединяющий интерфейс (Developer)
- фабричный интерфейс

2/) Abstract Factory
- объединяющий интерфейс (Developer Tester....)
- фабричный интерыейс

3/) Singleton
- один экземпляр класса
- и к нему глобальная точка доступа

4/) Builder
- отделение сущности от реализации
- используется абстрактный класс

5/) Prototype
- копирование экземпляра

**СТРУКТУРНЫЕ ПАТЕРНЫ**

1/) Adapter
- преобразование одного интерфейса верхнего уровня к другому, необходимому (Servise->DAO)

2/) Bridge
- предотвращение жеской привязки абстракции от ее реализации
- легкость доп.реализаций системы

3/) Composite(компоновщик)
- компоновка мелких компонентов в более крупные

4/) Decorator
- расширение функциональности, реализация подобных сущностей через декоратор

5/) Facade
- изоляция подсистем (похож на Компоновщик.. Team)
- в Фасаде только прописываются поля и делается вся работа

6/) Flyweight (приспособленец)
- поддержка множества мелких объектов

7/) Proxy
- контроль доступа к нашему объекту
например, требуется создать объект, но загружать его из репозитория только по обращению к нему

**ПОВЕДЕНЧЕСКИЕ ПАТТЕРНЫ Conclusion**

1/) Chain of Responsibility
- связывание объектов в цепочку
- передача запросов в эту цепочку
(избегаем привязки объекта запроса к объекту оьращения)
(объект не должен знать кто именно обработает запрос)

2/) Command
- параметризация объектов!
- выполнять запрос в разное время..

3/) Interpretetor
- определение представления граматики объекта
- просмотр резюме, выявдение Java и J/EE разработчиков

4/) Iterator

5/) Mediator (посредник)
- инкапсуляция. множество объектов
- нельзя использовать повторно объект (сложная связь, Admin-User)

6/) Memento (хранитель)
- хранение внутреннего состояния объекта за его пределами (не нарушая инкупсуляцию)
- его воссановления в случае необходимисти

7/) Observer (наблюдатель)
- определение зависимости one-to-many
- при изменении одного объекта, зависимые - получают уведомление, обновляются

8/) State (состояние)
- поведение управление объектом в зависимости от его состояния
- ..встречаеся большое количество условных операторов..

9/) Strategy (стратегия)
- необходимо иметь несколько вариантов поведения

10/) Template method (Шаблонный метод)
- подклассы могут переопределять часть класса, не изменяя его структуры в целом
- нужно управлять расшитениями подклассов

11/) Visitor (Посетитель)
- операции с каждым! объектом структуры
- объекты многих классов, частое добавление операций..
